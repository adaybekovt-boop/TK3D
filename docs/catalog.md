# TK3D catalog and source library

`catalogs/generators.json` is the canonical catalog. Its package mirror at
`src/geoforge/catalog/generators.json` is generated by
`scripts/consolidate_libraries.py` and must remain byte-identical.

Each entry records:

- stable `id`, semantic `capability`, `category`, tags, variants and description;
- `current_tk3d_status`: `NATIVE`, `ADAPTED`, `REFERENCE`, or `UNSUPPORTED`;
- source project, normalized `repository`, real SHA-only `pinned_commit`, license;
- `upstream_source`, repository-relative `local_source`, symbol/factory when identifiable;
- `source_available`, content SHA-256, runtime dependencies and reuse difficulty;
- runnable `kind`/adapter/implementation path only for working runtime entries.

`main`, `master`, `local-harvest`, and `unknown` are preserved as
`source_revision`, never misrepresented as pinned commits. Missing upstream
commit SHAs are counted in `catalogs/integrity.json`.

The object harvest contains several capabilities backed by one source file.
Those records remain separate. Deduplication removes only records with identical
repository, pinned commit, upstream path, symbol, and semantic capability.

The raw object-harvest catalog, rejected/gap list, research fragments, and source
notes are preserved under `catalogs/raw/object-harvest/`. Rejected research rows
are not promoted to generator entries.

No file under `library/` or `vendor/` is imported by the TK3D runtime. Adaptation
must produce an explicit builder under `src/geoforge/adapters/`, add a catalog
status transition to `ADAPTED`, and pass the existing geometry QA.
